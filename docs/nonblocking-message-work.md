# 避免图片与分类阻塞群消息

旧实现直接在事件循环中下载图片、解码图片和运行分类模型。
慢操作期间其它群消息及 WebSocket 回执也必须等待。

下载现使用异步 HTTPX，保持 8 MiB 流式上限；下载槽满立即跳过增强处理。
分类的导入、初始化及推理使用单线程，标签向量缓存最多 16 组。
图片计算使用独立线程池。提交前限制总工作数，超时/取消不会提前释放仍在运行的名额。

`config/worker_limits.json` 按修改时间读取，无周期检查：分类固定 1 线程/4 等待，
图片 2 线程/2 等待，下载并发 2/超时 10 秒，工作结果等待上限 30 秒。
数值可配置；损坏配置保留上次有效值。线程无法强制终止，超时后结果被丢弃，
该线程实际结束前仍占名额；关闭服务会等待运行中的工作并取消尚未启动的工作。

离线复现与回归（虚拟环境，UTF-8）：

```powershell
$env:PYTHONIOENCODING='utf-8'
python -m unittest scripts.test_async_message_work -v
python -c "import reverse_bot; print('Import OK')"
```

使用事件屏障、模拟 HTTP 流和分类器，不下载真实模型，不访问真实 QQ 或网关。
测试确认慢操作期间其它协程可运行、容量不会溢出、取消后保留运行名额、
下载限长、损坏图片降级、配置缓存及资源关闭行为。

文字命令另行回归：`python -m unittest scripts.test_text_command_regression -v`，使用临时签到/菜单数据，覆盖签到归属、吃啥、帮助与管理员权限。
