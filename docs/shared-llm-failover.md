# 统一聊天模型调用

旧聊天链先运行主脚本，失败后再运行备用脚本；两个进程各自尝试完整模型池，
冷却状态也各自从空开始。离线基线中 9 个模型全部返回 404，会产生 18 次请求。

聊天现在直接调用主进程模型池，同一轮每个候选最多尝试一次；9 个故障候选最多
请求 9 次，之后聊天、识图或命令可立即看到相同冷却状态。每次尝试前再次检查冷却。
内容校验回调只拒绝当前结果，不设置全局故障冷却，也不另开一轮预算。

独立脚本仍保留 JSON 调试接口，两者与主进程共用提示词和前缀清理。
已有短句校验、回复去重及画像外层重试均保持原语义，留给后续专项 PR。
严格墙钟预算依赖「超时保护」PR，合并本项前需先合并该 PR；本分支不夹带它的提交。

离线复现与回归（虚拟环境，UTF-8）：

```powershell
$env:PYTHONIOENCODING='utf-8'
python -m unittest scripts.test_shared_llm_calls -v
python -c "import reverse_bot; print('Import OK')"
```

测试使用模拟 HTTP 响应和独立脚本空输入，不访问真实网关；覆盖 9 次上限、
后续共享冷却、立即停止鉴权错误、业务校验继续、取消传播和 JSON 入口。
基线与回归请求次数可以比较；模拟耗时不代表真实模型性能。

文字命令另行回归：`python -m unittest scripts.test_text_command_regression -v`，使用临时签到/菜单数据，覆盖签到归属、吃啥、帮助与管理员权限。
